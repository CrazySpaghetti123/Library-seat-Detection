## Context

展示層現況：Jinja2 SSR + Bootstrap 5.3.3（CDN）+ 原生 JS，無建置流程。四個模板（`base` / `login` / `map` / `dashboard`）、兩支 JS（`map.js` 渲染 SVG 平面圖與 WebSocket、`dashboard.js` 驅動 Chart.js 4.4.3）、一份 42 行的 `app.css`。

`app.css` 目前只做兩件事：定義四個座位狀態的色票 CSS 變數，以及 SVG 座位方塊的樣式。其餘外觀完全來自 Bootstrap 預設。

約束：不引入 build step（維持 CDN + 靜態檔的部署方式，之後上 Fly.io 時不需額外建置階段）；不改動後端與 API；`floor-map-web` spec 既有的顏色語意（綠／紅／橘／灰）為需求，不可改變其對應關係。

## Goals / Non-Goals

**Goals:**

- 建立可維護的設計 token 層，讓顏色、間距、字體有單一事實來源，取代散落的 Bootstrap 工具類別。
- 消除「狀態僅以顏色編碼」的可用性缺陷，使色覺辨識障礙使用者能判讀座位狀態。
- 支援深色模式，並讓 SVG 平面圖與 Chart.js 圖表都正確跟隨主題。
- 提升狀態變化的可感知性（即時系統的變更若無過渡，使用者容易錯過）。

**Non-Goals:**

- 不更換 CSS 框架（不改 Tailwind）、不改前後端分離架構。
- 不引入 npm / build step / CSS 前處理器。
- 不改變任何後端行為、API 契約、WebSocket 訊息格式。
- 不重新設計資訊架構或新增頁面；本次只做既有頁面的視覺與可用性升級。

## Decisions

### D1：以 CSS 變數建立 token 層，覆寫而非取代 Bootstrap

Bootstrap 5.3 本身即以 CSS 變數實作（`--bs-*`），因此可在 `app.css` 中重新定義 `--bs-primary`、`--bs-body-bg` 等變數來改變全域外觀，不需逐一覆寫選擇器。自訂 token 以 `--app-*` 命名以區隔來源。

**替代方案**：逐一撰寫高特異度選擇器覆蓋 Bootstrap。捨棄原因是特異度戰爭難以維護，且無法讓 Bootstrap 自身元件（modal、alert）跟著變色。

### D2：單一深色主題，`data-bs-theme="dark"` 硬寫於 `<html>`

系統採單一深色主題，不提供淺色版本或切換機制。`<html>` 標籤固定 `data-bs-theme="dark"`——Bootstrap 5.3 的深色元件樣式依賴此屬性——而自訂 token 因不需分支，直接定義於 `:root`。另加 `<meta name="color-scheme" content="dark">`，使瀏覽器原生控制項（捲軸、日期選擇器）一併採深色。

如此不需要主題初始化 script，也就沒有淺色閃爍（FOUC）的問題。

**替代方案**：保留淺／深雙主題與切換鈕。捨棄原因是本系統的使用情境（自習室、多為室內低光環境）與視覺定位單一，雙主題會使 token 層、圖表配色與毛玻璃參數都需維護兩組，成本不划算。

### D3：狀態以「顏色 + 圖示」雙重編碼

在每個座位方塊內除了標籤文字外，另繪製一個狀態圖示：可預約（✓）、使用中／已預約（●）、疑似佔位（⏱）、維修中（✕）。圖示為 SVG `<text>` 節點，與標籤同組渲染。

**替代方案一**：改用紋理／斜線填充區分。捨棄原因是 SVG pattern 在小尺寸方塊上辨識度差，且與深色模式的對比處理更複雜。

**替代方案二**：僅調整為色盲友善配色（如藍／橘取代綠／紅）。捨棄原因是 `floor-map-web` spec 明確要求綠／紅／橘／灰的對應關係，改配色等於改需求；加上圖示則是在既有語意上疊加資訊，兩者相容。

### D4：Chart.js 配色由 JS 讀取 CSS 變數

Chart.js 的顏色需在建構時以字串傳入，無法直接吃 CSS 變數。作法是在建圖前以 `getComputedStyle(document.documentElement).getPropertyValue('--app-chart-1')` 取得實際色值，使圖表配色與設計 token 維持單一事實來源，調整 token 即同步反映於圖表。

因採單一主題（D2），不需要在主題切換時重建圖表。

### D5：中文字體採系統字體堆疊，不載入網路字體

繁體中文字型檔即使經過子集化仍在數百 KB 至數 MB 之譜，載入成本與 FOUT 對本專案不划算。改用 `-apple-system` / `PingFang TC` / `Microsoft JhengHei` / `Noto Sans TC` 的堆疊，在各平台都能取得合適的無襯線中文字體。

### D6：狀態變更以 CSS transition + 一次性脈動動畫提示

座位填色加上 `transition`，並在 WebSocket 推送更新時對該座位加一個短暫的 class 觸發脈動，動畫結束後移除。此為即時系統的可感知性需求——若無提示，使用者容易錯過遠處座位的狀態變化。

動畫一律包在 `@media (prefers-reduced-motion: reduce)` 的例外處理中，尊重使用者的減少動態偏好。

### D7：表面採毛玻璃（backdrop-filter），座位方塊維持不透明

容器層（navbar、card、stat-tile、conn-badge、modal、alert、form control）改為半透明表面 + `backdrop-filter: blur() saturate()` + 一道半透明亮邊。

兩項配套為必要而非裝飾：

- **body 需要有層次的背景**。`backdrop-filter` 模糊的是元素背後的實際內容，若背後為純色則視覺上與單純的半透明無異。因此 body 加上三層固定的 radial-gradient 光暈作為取樣來源，捲動時玻璃面的透色會隨之變化。
- **座位方塊的處理見 D8**。座位本身亦為毛玻璃，並刻意採低對比的半透明標籤。

降級路徑有二：`@supports not (backdrop-filter: ...)` 時回退為不透明表面；`prefers-reduced-transparency: reduce` 時同樣關閉模糊與透明，尊重系統無障礙設定。行動裝置下模糊半徑由 16px 降為 10px，因 `backdrop-filter` 的成本隨模糊半徑與元素面積上升。

**替代方案**：以半透明背景搭配靜態的模糊背景圖模擬。捨棄原因是無法隨捲動與內容變化，且多一張圖片資源。

### D8：座位方塊＝毛玻璃底板 + 半透明狀態色，無邊框、無文字描邊

座位由兩層矩形構成，質感比照對話方塊（`.modal-content`）：

1. **`.seat-base`**：半透明白（`--seat-glass-base` .16）+ `backdrop-filter: blur(7px) saturate(150%)`
   + 一道 1px 極細亮邊（`--seat-rim` .12）。底板同時提供可預期的合成基底——
   少了它，狀態色會直接疊在深淺不一的頁面背景上，同一狀態在畫面不同位置會呈現不同顏色。
2. **`.seat-fill`**：均勻半透明狀態色（`--seat-fill-opacity` .84），無描邊、無漸層。

文字一律無描邊：標籤為半透明白（`--seat-label-opacity` .46），字身透出底下的狀態色；
狀態圖示則維持 `--seat-icon-opacity` .88，**刻意不隨標籤一起淡化**——
它是顏色以外的第二重狀態編碼（D3），色覺辨識障礙使用者靠它判讀座位能否使用。

座位背後不鋪任何地板層，平面圖卡片的 `background` 設為 `transparent`，
使座位背後與卡片外圍是同一個底。

**可讀性量測**（深色主題，經「頁面背景 → 卡片 → 底板 .16 → 狀態色 .84」合成後）：

| 狀態 | 合成底色 | 圖示對比 | 標籤對比 |
|---|---|---|---|
| 可預約 | rgb(51,143,102) | 3.48:1 | 2.01:1 |
| 使用中 | rgb(185,87,81) | 3.95:1 | 2.15:1 |
| 疑似佔位 | rgb(185,147,60) | 2.58:1 | 1.69:1 |
| 維修中 | rgb(103,113,128) | 4.28:1 | 2.33:1 |

標籤的低對比是設計意圖（「文字透明」的要求），座位編號另有位置與 tooltip 可輔助辨認；
圖示維持較高對比，以保住無障礙那一層。四種狀態色中最需要被區分的是
「使用中（紅）」與「疑似佔位（琥珀）」——能坐 vs 不能坐——兩者色相差 **38°**，
原先的橘紅方案僅約 10°，曾被反映難以分辨。

**瀏覽器支援**：SVG 圖形元素上的 `backdrop-filter` 在 Chromium 與 Safari 可用，
Firefox 可能無效。`@supports` 降級時將底板不透明度提高至 .26 補回層次，不會變成一片糊。

**回退方式**：`--seat-fill-opacity: 1` 即回到不透明座位，無需改動 JS 或結構。

## Risks / Trade-offs

- **主題切換時 Chart.js 需重建圖表** → 若使用者正在檢視查詢結果，重建會短暫閃爍。緩解方式是僅在圖表已有資料時重建，並保留既有的查詢結果資料不重新請求 API。
- **座位圖示在小尺寸螢幕上可能過小** → 於 360px 寬時圖示與標籤的相對尺寸需另行調整，列入 RWD 驗證項目。
- **深色模式下座位狀態色的對比度** → 淺色模式的飽和色在深色底上會過亮刺眼，需為深色模式定義另一組較低亮度的狀態色，並確認與白色標籤文字的對比度仍達 WCAG AA（4.5:1）。
- **`data-bs-theme` 依賴 Bootstrap 5.3+** → 已使用 5.3.3，但 CDN 版本若日後升級需留意此屬性的相容性。
- **無自動化視覺測試** → 樣式變更無法由現有 pytest 套件覆蓋，需以手動檢查清單（淺／深色 × 桌面／手機 × 四種座位狀態）驗證。
- **毛玻璃降低文字對比** → 半透明表面上的文字，其實際對比度取決於背後透出的內容。緩解方式是背景光暈的 alpha 控制在 .16 以下、玻璃表面不透明度不低於 .55，並於數據卡片等文字密集處改用不透明度較高的 `--app-glass-bg-strong`。
- **`backdrop-filter` 的繪製成本** → 大面積或高模糊半徑在低階裝置上可能掉幀，尤其捲動時。緩解方式是行動裝置降低模糊半徑，且不對大面積的 `main` 或 `body` 套用。
